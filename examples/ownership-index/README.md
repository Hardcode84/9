# Tutorial: a one-way symbol index

A compiler can give several aliases to one symbol. The aliases refer to the
symbol, but the symbol has no pointer back to them. Removing the symbol must
also remove those references. This example shows that obligation with the same
ownership stage used by the [intrusive list](../intrusive/README.md).

```sh
make all ownership-stage
build/crust examples/ownership-index/main.crs
build/ownership-index
```

The result is `OK`. [main.crs](main.crs) explicitly trusts
[provider.crs](provider.crs). It checks all of [program.crs](program.crs),
including the helper functions. No index rule is added to the compiler.

## Representation and ownership

The complete storage interface is:

```crust
domain Symbols(Symbol, Alias, Index, Selection);
record Symbol { next: *Symbol; key: i64; value: i64; } opaque;
record Alias { next: *Alias; target: *Symbol; key: i64; } opaque;
resource Index { symbols: *Symbol; aliases: *Alias; } opaque drop index_drop;
record Selection { target: *Symbol; } opaque scoped;
```

`Index` owns two ordinary singly linked lists: symbols and aliases. Each entry
has its own allocation. `Alias.target` does not own its target. Several aliases
can refer to the same symbol. An unbound alias has a null target. Symbol keys
and alias keys use separate namespaces.

`Selection` contains one pointer. It borrows an access scope, not ownership of
the symbol. A payload loan from `selection_value` also borrows the selected
storage. The checker prevents that loan from surviving reclamation or conflicting
with an edit. Opaque fields prevent clients from retaining untracked pointers.

These are the API effects:

| Operation | Access | Behavior |
| --- | --- | --- |
| `index_new` | `reclaim` | Return an empty owner. |
| `index_insert` | `reclaim` | Allocate a symbol with a distinct key. |
| `index_alias` | `reclaim` | Allocate an alias; a missing target leaves it unbound. |
| `index_bind` | `edit` | Change an existing alias without destroying either target. |
| `index_remove` | `reclaim` | Unbind incoming aliases, then remove and free one symbol. |
| `index_select` | `read` | Return a selection for an alias. |
| `selection_value` | `read` | Borrow the payload with `from selection`. |
| `drop index` or scope exit | `reclaim` | Free aliases, then symbols. |

Duplicate insertion and allocation failure trap. `index_remove` and
`index_bind` return false for an absent entry. `selection_present` tests for an
absent result. Requesting its payload traps. These are explicit collection
operations; the ownership stage inserts no pointer validity checks.

## Retirement with one-way pointers

`index_remove` walks the symbol list to find the owning link. It then scans
every alias and clears each reference to that symbol. Only then does it unlink
and release the symbol. Deletion costs `O(symbols + aliases)`. There is no
reverse index, generation counter, or hidden scan generated by the checker.

Both parts of the order matter. Clearing only one alias leaves another dangling.
Reallocating the same address without clearing the aliases would make them
refer to a different symbol. The example removes a symbol with two aliases,
checks that both are unbound, and inserts a replacement with the same key.
The aliases remain unbound until the program explicitly binds them again.

An edit can change an alias while a selection keeps its old target. This is
valid because edit access cannot retire that target. A payload borrow blocks
conflicting edits. Once the read or edit scope ends, the program can reclaim
symbols and create fresh selections in a new scope.

The index destructor frees aliases before symbols. The example also leaves
a runtime-sized set of entries for automatic cleanup. The trusted provider
must maintain these rules. The compiler checks the client contracts; it does
not prove the provider's pointer stores.

## Checked helpers and view origins

`remove_required` is an ordinary checked wrapper around `index_remove`. Its
`mut Index` loan protects the owner handle itself. It can forward that loan
to another reclamation operation. It cannot drop the borrowed handle. A live
payload loan still prevents reclamation.

`expect_alias` combines two independent loans in a local `Comparison`: the
selected symbol value and the caller's expected value. It passes the record
to `comparison_equal`. No lifetime map is needed because the record does not
escape those inputs.

The [stored-view example](../ownership-basics/views.crs) also obtains separate
single-origin results, combines them locally, and replaces a local view after
`drop`. Keep these interfaces for this ownership profile. Returning several
independent origins in one record, or replacing origins through `mut View`,
is rejected. Accepting either would require an explicit origin map on the
function boundary. These examples do not require that additional interface.

## Check the boundary

```sh
make check-ownership
python3 tests/ownership_index.py --sanitize
```

The test runs optimized and unoptimized native programs with ASan and UBSan.
It compares C and symbol bytes before and after ownership verification. A test
allocator forces exact-address reuse and checks that all allocations are released.
The allocator is test code; the example uses ordinary `malloc` and `free`.

The test also removes the provider and helper sources before compiling an
imported client. Rejection cases cover stale selections, escaped payloads,
reclamation during access, private fields, unreported observers, handle aliases,
and direct or deferred destructor calls. It checks ordinary and imported
reclamation helpers. All checks use the existing stage API.
